# Walkthrough 5.3: error cases

Written on 2026-11-16, right after the exercise.

## The idea

Every mistake a user can make should end with one readable line and a meaningful exit code, never with a traceback. Most of this already worked after 5.1, because the code below the command line was written to report errors. This exercise added the one missing case (Ollama), made long errors short, and wrote a test for every row.

## The table

| Case | What the user sees | Exit | Where it is handled |
|------|--------------------|------|---------------------|
| `--repo` is not a Git repository | `Error: Not a git repository: <path>` | 2 | `GitError`, caught in `main` |
| Unknown or malformed commit | `Error: Unknown commit: ...` or `Error: Not a commit SHA: ...` | 2 | `GitError`, caught in `main` |
| Commit without reviewable Python | `Nothing to review: ...` with the reason | 0 | Step 2 of `run_review` |
| Missing key, invalid setting | The name of the variable; for the key also the hint `LLM_PROVIDER=ollama` | 2 | `ConfigError`, caught in `main` |
| Ollama not running, model not pulled | How to start Ollama, or which `ollama pull` to run | 3 | `OllamaError`, caught in `main` |
| API error or rate limit | `FAILED: ...` for that file, the others continue | 3 | `result.error` |
| Structured output invalid twice | `FAILED: ...` for that file, the others continue | 3 | `result.error` |

Exit 2 means "fix your input or settings". Exit 3 means "the input was fine, but a review did not work".

## The steps

### Step 1: two kinds of errors, two ways to handle them

Look at the last column of the table. There are only two mechanisms:

- **Errors that stop everything** are exceptions (`GitError`, `ConfigError`, `OllamaError`). They travel up to `main` in [cli.py](../src/reviewgraph/cli.py), which has one `except` per exit code.
- **Errors of one file** are not exceptions at the command line. `review_agent` and `review_baseline` catch them and write them into `result.error`, so the loop over the files goes on.

### Step 2: the new piece, `check_ollama` in [llm.py](../src/reviewgraph/llm.py)

Without it, a stopped Ollama would make all 13 files of a commit fail one after the other with the same connection error. The function asks the server one small question (`client.show(model)`, the same as `ollama show` in the terminal) and translates the two possible failures:

- The server answers "404": the model is not installed. The message names the `ollama pull` command.
- No connection: the server is not running. The message says how to start it.

For Gemini the function returns at once. It is not a model call, so it costs nothing.

### Step 3: where it is called

Step 3 of `run_review`, directly after `get_chat_model()`. So the order of 5.1 still holds: Git first, then the files, then the model.

### Step 4: `raise ... from None`

You see this in `check_ollama`. When an exception is raised inside an `except` block, Python normally shows both errors ("During handling of the above exception, another exception occurred"). `from None` hides the first one, because our message already says everything the user needs.

### Step 5: `one_line` in [report.py](../src/reviewgraph/report.py)

A Gemini rate-limit error is many lines of JSON. `one_line` joins the text to one line and cuts it after 300 characters. It is used for the `FAILED:` line on the screen and for `**Not reviewed:**` in the Markdown. `review.json` keeps the full error.

### Step 6: the tests, one per row

They are in the section "Exercise 5.3" of [test_cli.py](../tests/test_cli.py). Three helpers are worth understanding:

- `no_model` replaces the model factory with a function that fails the test. If a test with this fixture passes, no model was created, so no LLM call was possible.
- `environment` lets a test set environment variables. `get_settings()` remembers its result (`@lru_cache`), so the fixture empties that memory before and after the test.
- `use_ollama` replaces `ollama.Client.show` with a function that raises the error the real server would give. The tests need no Ollama.

## Tried by hand

Against the real Ollama server on 2026-11-16:

```
OLLAMA_MODEL=no-such-model:1b      -> Error: The Ollama model no-such-model:1b is not installed. Run `ollama pull no-such-model:1b` and try again.   (exit 3)
OLLAMA_BASE_URL=http://localhost:1 -> Error: Ollama is not running at http://localhost:1. Start the Ollama app or run `ollama serve`, and try again.  (exit 3)
```

## Not covered

- An error that is not in the table (a bug in the code) still shows a traceback. That is on purpose: a traceback is what you need to find a bug.
- If you stop a run with Ctrl+C, the files reviewed so far are not written to a report.
- The API error rows are tested with the scripted model only. A real Gemini failure through the command line has not been run.
