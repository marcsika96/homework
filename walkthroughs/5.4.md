# Walkthrough 5.4: the local path

Written on 2026-11-16, right after the exercise.

## The idea

The homework needs a way to run the system without paying and without a key. That is the local path: `LLM_PROVIDER=ollama`. This exercise is mostly measuring and writing down, not coding. It has one small piece of code and one piece of documentation.

## The steps

### Step 1: does the model support tools?

The agent hands three tools to the model. A model that cannot produce tool calls fails at the first `lookup`. The plan says to check with `ollama show <model>`; its output has a section "Capabilities":

```
Capabilities
  completion
  tools
```

Checked for every model on the laptop: all of them list `tools`, including the default `qwen2.5-coder:7b`. So the example in the specification stays as it is.

### Step 2: the same check, done by the program

Reading `ollama show` by hand is easy to forget, so `check_ollama` in [llm.py](../src/reviewgraph/llm.py) now does it. It was already asking the server for the model's details (5.3). The answer has a field `capabilities`, a list like `["completion", "tools"]`. The new lines:

- `needs_tools` is a new argument. The command line passes `True` for the agent and `False` for the baseline, because only the agent calls tools.
- If tools are needed and `"tools"` is not in the list, it raises `OllamaError` with the two ways out: another model, or `--system baseline`.

The call in [cli.py](../src/reviewgraph/cli.py) is `check_ollama(needs_tools=args.system == "agent")`. Read the right side first: `args.system == "agent"` is a comparison, so it is `True` or `False`, and that value is passed on.

### Step 3: the tests

Three tests in [test_cli.py](../tests/test_cli.py), next to the other Ollama tests. The helper `shows("completion")` builds a fake answer of the server. `SimpleNamespace(capabilities=[...])` is the shortest way in Python to make an object with one attribute; the check reads nothing else.

### Step 4: what the local models can do

No new run was needed: the benchmark of the same day already ran the baseline and the agent on dev unit 20 with two local models. The table is in `notes.md` under "Local path". In short:

| | Gemini | Local models on this laptop |
|---|--------|------------------------------|
| Time per review | about 1 minute | 5 to 26 minutes |
| Tool calls | 6 of 8 | 0 |
| Known defect found | yes | no |

### Step 5: the lesson in it

"Supports tools" and "uses tools" are different things. `ollama show` tells you the model **can** produce a tool call. Whether it **decides** to look something up is a question of how capable the model is. The small models answered directly every time, so with them the agent is the baseline plus a self-check.

That is why the check in step 2 can only catch the first problem, and why the second one is documented as a limitation instead.

### Step 6: where this goes

The plan allows a documented limitation of the key-free path. The paragraph for the README is drafted at the end of the "Local path" section in `notes.md`. The other key-free path is the cached evaluation of Part 6.
