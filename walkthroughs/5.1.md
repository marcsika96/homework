- [graph.py](../src/reviewgraph/graph.py): `review_agent` got an `on_step` argument. Only the part below the marker line changed.

How to call it:

```
reviewgraph review --repo <path> --commit <sha> [--system agent|baseline] [--verbose]
python -m reviewgraph review ...
```

## The steps

Open `cli.py` and read it in this order.

### Step 1: `main` is the front door

It does three things: it parses the arguments, calls `run_review`, and catches `GitError` and `ConfigError`. Those two become one `Error: ...` line and exit code 2 instead of a traceback. The function returns a number, and the shell sees that number as the exit code.

### Step 2: `build_parser` describes the command line

`add_subparsers` is what makes `review` and `eval` separate commands. After parsing, the values are read as `args.repo`, `args.commit`, `args.verbose`.

### Step 3: `run_review` is the real work, in numbered steps

The order is the important idea:

1. Open the repository and resolve the commit. This is Git only.
2. Collect the files to review with `is_reviewable`.
3. Only now create the model.
4. Review the files one after the other.
5. Pick the exit code.

Because the model is created in step 3, a wrong path or commit fails in step 1 and never costs an LLM call.

### Step 4: why the loop survives a failed file

There is no `try` in the loop. `review_agent` and `review_baseline` never raise for a failed review; they put the problem into `result.error`. So the loop just continues, and at the end any result with an error makes the exit code 3.

### Step 5: how `--verbose` reaches the graph

`print_step` in `cli.py` is a normal function that is passed to `review_agent` as `on_step`. Inside `_review_with_graph` the graph streams in two modes at once, so each item is a pair `(mode, data)`:

- `"values"` is the whole state. The last one is kept, so the trace survives a failure.
- `"updates"` is `{node name: what the node returned}`, which is handed to `on_step`.

This is the same `"updates"` stream as in `scripts/try_graph.py`.

### Step 6: the tests replace the model

`use_model` in `test_cli.py` swaps `cli.get_chat_model` for a function that returns the scripted model. The `no_model` fixture swaps it for a function that fails the test. That failure is the proof that a case was answered without an LLM call.

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | Every file was reviewed, or there was nothing to review |
| 2 | Wrong repository, commit or configuration |
| 3 | At least one file could not be reviewed |

## Things that differ from what you might expect

- Files without added lines are skipped. This covers deleted files, which would otherwise fail when the review reads the file at the commit.
- `eval` only prints "not written yet" and exits with 2 until Part 6.

## Changed by Exercise 5.2

- `--out` is used now: the reports are written to `<out>/<sha7>/`.
- The per-file summary became one progress line, because the full report is printed at the end.
