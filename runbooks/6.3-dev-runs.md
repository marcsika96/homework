# Runbook: the dev runs of Exercise 6.3

Written on 2026-11-16 for whoever starts the runs: me, or a Claude Code agent I ask to do it. Everything here is for the **dev units only**. All commands are run from the `homework` folder in PowerShell.

## What these runs are for

6.3 is: run both systems and the judge on the 26 dev units, read the findings and the verdicts, improve the prompts, repeat, then freeze. This runbook covers the first round of runs. Reading the results and changing prompts is my work and is not part of it.

## Rules that must not be broken

1. **Never run the test set.** Do not pass `data/units_test.jsonl` and do not pass `--test-set`. The default units file is the dev file, so no `--units` argument is needed.
2. **One model job at a time.** Check that the overnight phi run is finished before starting anything (see "Before starting"). Two Ollama jobs on this laptop make both useless.
3. **Do not change prompts, the graph or the judge.** Only run and report.
4. **Do not use Gemini without asking me.** The free tier is 20 requests per day. The baseline on all dev units is 26 requests, the agent about 260.
5. **Do not stop a run with Ctrl+C unless something is wrong.** If it has to be stopped, nothing is lost: finished units are stored and the same command continues.

## Long runs: keep the laptop awake

The laptop goes to sleep after 30 minutes without input, which pauses a run. `scripts\run_awake.ps1` runs a `reviewgraph` command and keeps Windows awake until it has finished, without changing a power setting. Its first argument is the log file, the rest goes to `reviewgraph`. Closing the lid still puts the laptop to sleep.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_awake.ps1 out\dev-runs-phi4.log eval --runs data\runs-phi4 --verdicts data\verdicts-phi4.jsonl
```

Normal output goes to the log file, error messages to `<log file>.err`, and the last line of the log is the exit code. For every command below that ends in `*> out\<name>.log`, this form is the better one for a run of more than half an hour.

## Option A: local model (free, slow, works now)

This is the only option without quota. It shows that the whole pipeline works on all 26 dev units and gives real timing numbers. It is of little use for tuning the prompts: the local models made no tool calls and missed the known defect (see "Local path" in `notes.md`).

```powershell
$env:LLM_PROVIDER = 'ollama'
$env:OLLAMA_MODEL = 'phi4-mini:3.8b-q4_K_M'
.\.venv\Scripts\python.exe -u -m reviewgraph eval *> out\dev-runs-phi4.log
```

- Estimated time: baseline about 5 minutes per unit, agent about 12, so roughly 7 hours for the 26 units with both systems. Laptop plugged in, sleep switched off.
- A shorter first step: add `--system baseline` (about 2 hours), or `--limit 5`.
- Progress: `Get-Content out\dev-runs-phi4.log -Wait`
- Then the judge, one request per selected finding:

```powershell
.\.venv\Scripts\python.exe -u -m reviewgraph eval --judge *> out\dev-judge-phi4.log
```

The `$env:` lines apply to that terminal window only. `.env` stays on Gemini.

## Option B: Gemini baseline (needs quota, ask first)

The baseline needs one request per unit, so the 26 dev units fit into two days of free quota. This is the useful input for tuning the reviewer prompt.

```powershell
.\.venv\Scripts\python.exe -u -m reviewgraph eval --system baseline *> out\dev-runs-gemini.log
```

It stops by itself when the daily quota is used up (exit code 3, last line "Stopped: the daily quota is used up"). The same command on the next day continues with the next unit. In a new terminal `LLM_PROVIDER` is not set, so `.env` (Gemini) applies; check with `echo $env:LLM_PROVIDER` that it is empty.

The agent on Gemini (about 10 requests per unit) does not fit into the free tier. The plan for it is Google Colab with a larger open model, which is not tried yet.

## Do not mix A and B in the same folder

A stored run of another model is run again and **replaced** (rule 4 of the rerun rules in `notes.md`). So if the phi runs are in `data/runs/` and a Gemini run starts, the phi runs are overwritten unit by unit, and the other way round. To keep both, give the local runs their own folders:

```powershell
.\.venv\Scripts\python.exe -u -m reviewgraph eval --runs data\runs-phi4 --verdicts data\verdicts-phi4.jsonl *> out\dev-runs-phi4.log
```

Recommended: use these separate folders for Option A, and keep `data/runs/` and `data/verdicts.jsonl` for the model of the real evaluation.
