## Review units

A review unit is one changed Python file in one increment commit. It is reviewed with the repository as it was at that commit, so code from later increments cannot leak in.

A changed file becomes a unit if all of these hold (`is_reviewable` and `build_units` in `src/reviewgraph/schemas.py`):

- its path starts with `app/studio/` and ends with `.py`;
- it is not under a `migrations/` folder;
- its file name does not start with `seed_` (seed data: `seed_data.py`, `management/commands/seed_demo.py`);
- the commit adds at least 15 lines to it, as counted by `git diff-tree --numstat` against the parent commit. Renames are not followed.

Each line of the unit files is one JSON object:

```json
{"id":"I4:app/studio/backend/pages.py","increment":"I4","commit":"c89ea07e0ac722b93a731c97c5d882482b86c865","path":"app/studio/backend/pages.py","added_lines":18,"split":"test"}
```

| Split | Increments | Units | Added lines (sum) | Added lines per unit (min / median / max) | Use |
| --- | --- | --- | --- | --- | --- |
| dev | I1–I3 | 26 | 1,018 | 15 / 28 / 218 | Tuning the reviewer and judge prompts |
| test | I4–I8 | 36 | 1,547 | 16 / 31 / 167 | Evaluation only |

The split follows time: every dev unit is older than every test unit, and no commit contributes to both.

## Freeze

The test set was frozen on 2026-11-12 in commit `ddc21c7`, before the reviewer, the baseline or the judge existed.

- SHA-256 of `data/units_test.jsonl`: `50e9c9dfd58b5f3c577414a4def7d423d4ae634db19e2563384703043526d5de`
- `tests/test_dataset.py` fails if the file changes.
- `.gitattributes` keeps LF line endings for the files in `data/`, so the checksum is the same on Windows and Linux.

## Reproducing the unit files

```bash
python scripts/get_target.py     # clones or fetches the target, writes data/increments.json
python scripts/build_units.py    # writes data/units_dev.jsonl and data/units_test.jsonl
```

Running both again produces byte-identical files.

## Excluded, and why

- **Templates, JavaScript, CSS**: out of scope for the reviewer (see the specification).
- **Tests of the target (`app/tests/`) and project settings (`app/dsw/`)**: the reviewer looks at application code only.
- **Migrations and seed data**: generated or pure data, nothing to review. None of the eight increment commits changes such a file, so this rule currently removes no unit.
- **Files with fewer than 15 added lines**: too little change for a meaningful review.

## Secrets

The history of the target was searched for committed keys and passwords on 2026-11-12. It contains none: `.env` was never committed, `.env.example` holds placeholders, `app/dsw/settings.py` reads every secret from the environment, and the passwords in the tests and in `seed_demo.py` are development-only demo values.
